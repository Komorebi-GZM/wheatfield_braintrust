# 阶段A 一页版（对内）：三个因子跑完，结论与待办

> 全部实验在固定验证集 **5 页**上（参考均无 `□`，5 页全可评分），`max_pixels=1024000`、`max_new_tokens=1024`、后处理一致；**未碰 test**。详细证据见 `phase_a_cap_report_v4.md`、`phase_a_prompt_report_v4.md`、`HANDOFF.md` §12–§13。原始预测在 `outputs/phaseA/`（未入库）。

## 一、结论（三句话）

1. **生成上限不是瓶颈**：1024→2048 对 3/5 页零影响；唯一自然结束的页追加的是同一套臆造模板，另一页把重复写得更长并触顶。→ 2048 不做默认。
2. **提示词能压掉臆造模板，但不能当改进**：自造小标题 139→7、重复条目 26%→0.9%，可 A/B 都换来欠生成（字数/参考 1.64→0.68/0.70）与公式丢失（含公式宏 CER 0.775→1.041/1.085）。→ 提示词线收口。
3. **解码侧是目前唯一同时压住两个病灶的设置**：重复惩罚 1.1 + `min_new_tokens` 256 把正文宏 CER 从 **1.248 降到 0.825**、含公式宏 CER 基本持平（0.775→0.800）、字数比 1.64→1.07、重复条目 26%→**0%**、触顶 2→0、被判重复 2→0，且更快（275 s→195 s）。

**逐页胜负（正文 CER）**：冻结 3 页、解码 2 页。但解码赢的两页是**大幅**（235955 2.981→0.921、235946 0.962→0.722），输的三页是**小幅**（+0.067 / +0.014 / +0.103）——这正是宏平均从 1.248 降到 0.825 的来源。**不能只看胜负数，也不能只看宏平均**，两个都要报。

**基座臂**：冻结 15.955（被 000005 的 45-token 早停崩坏拉爆）→ 解码 1.181。但要如实写：解码同时把原本正常的页变差（235932 0.544→0.915、000012 0.753→1.311），它是"去掉灾难性崩坏、换来普遍中等"。基座的宏平均在这里同样不可单独引用。

## 三、必须写明的局限

1. **解码侧两个参数是同时改的**（rp 1.1 与 min_new 256），按"一次一个因子"原则这属于**混杂**：无法区分是抑制重复起效，还是最小长度把早停页强行拉长。**需要补消融**（只 rp / 只 min）。
2. 5 页样本，宏平均方差大；235955 与 000005 两页主导了大部分差异。
3. 含公式宏 CER 在解码侧略升（0.775→0.800），说明抑制重复会让部分公式被压掉，评测必须继续同时报两列。
4. `min_new_tokens=256` 会强制短页继续写，个别页（000012、000005）可能因此加入本不该有的内容；本报告未逐字核对这些新增内容对不对。
