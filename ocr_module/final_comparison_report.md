### 1.5 "是否有 PDF 补写"

- `物理。.pdf` 经结构检查为**纯扫描件**：13 个页对象、0 个字体、0 个 ToUnicode → 不可能从中"复制文本"，只可能"照打印版抄写"。
- 若是照打印版抄写，标注应趋向标准教材值；而实测正好相反：200858 的 `5.119×10⁷`、`0.515Ω`、200917 的 `37.326-1.203`、200903 的 `R+1` 都是**原图特有的、不标准的写法**，标注逐一保留。→ **不支持"从 PDF/教材补写"的假设**。
- 真正存在的是**另一种补写**：①结构补写（235916 凭空加表头）、②知识补写（000037 把 `D6D5` 写成 `D6D5D4`）、③`□` 政策不一致（22 页仅 3 个 `□`，实际手写页不可能这么"清楚"）。

**结论**：真实标签可作为训练弱监督，但**不能宣称是逐字真值**。测试集的 5 页参考已全部逐页对照，可用作评测基准，但 000037 那一位需要修。

## 2. 第 2 步：预测文件检查与生成上限

### 2.1 三个预测文件的实际状态

| 文件 | 行数 | 覆盖页 | 说明 |
|---|---|---|---|
| `outputs/baseline/test_pred.jsonl` | 5 | 全部 5 页 | 早期跑，环境默认 `OCR_MAX_NEW_TOKENS=4096`，000051 输出 7156 字符 |
| `outputs/baseline/test_pred_512.jsonl` | 5 | 全部 5 页 | 512 上限重跑，000051 输出 884 字符 |
| `outputs/finetuned/test_pred_512.jsonl` | **1** | 仅 000020 | **不完整**，缺 000028/000037/000044/000051 四个可评分页 |

更正一处交接描述：微调版**不是"首条预测写出前停止"**，磁盘上已落盘 1 条（000020，786 字符，耗时 109.8 s），只是后续 4 页没有继续。而唯一落盘的这页恰好是 `□` 页，评测时会被整页排除——所以微调版**有效评测页数为 0**。

### 2.2 两次基座运行的关系（决定上限怎么选）

逐字符比对 4096 与 512 两次运行：

| 页 | 4096 输出 | 512 输出 | 是否完全一致 |
|---|---|---|---|
| 000020 | 205 字符 | 205 字符 | 一致 |
| 000028 | 532 字符 | 532 字符 | 一致 |
| 000037 | 628 字符 | 628 字符 | 一致 |
| 000044 | 717 字符 | 717 字符 | 一致 |
| 000051 | 7156 字符 | 884 字符 | 不一致（都被截断，长度不同） |

4 个可评分页在两种上限下**字节完全相同**，说明它们在 512 token 内自然收敛（模型自己停了）。唯一受上限影响的 000051 是**退化重复**，不是"内容没写完"：

- 512 上限：`OCW1/OCW2/OCW3` 三个标题之后立刻进入 `D D D` 循环，884 字符内含 114 组 `D D D`；
- 4096 上限：同一循环一路跑到上限，7156 字符，仍无有效内容。

即：**加长上限不恢复正确内容，只会把垃圾拉长并把 CER 推高（1.4 万 % 那一页就是这样来的）。**

### 2.3 选定结果

> **统一生成上限：`max_new_tokens = 512`，基座与微调版一致，解码保持 `do_sample=False`。**

配套判定规则（写进报告口径，不改代码）：

1. 输出达到 512 且末段出现连续重复片段（如连续 3 次以上 `D D D`）→ 标记 `generation_failure`，**主指标与失败页指标分开报告**，不当成"识别错误"混进均值。
2. 未触顶且以正常结构收尾 → 视为完整预测。

理由：① 4/5 页已被证明在 512 内自然结束；② 最高参考长度 683 字符（000028），512 token 对该模型约合 880+ 字符的产出空间，够用；③ 与已完成的 `test_pred_512.jsonl` 同口径，恢复时只需补微调 4 页。

**待办（恢复后执行，本次未运行）**：

```bash

OCR_MAX_NEW_TOKENS=512 python scripts/infer_test_baseline.py \
  --manifest datasets/handwriting_notes/splits/test.jsonl \
  --output outputs/finetuned/test_pred_512.jsonl \
  --adapter outputs/qlora-v1/v2-20261115-114258/checkpoint-4
```

⚠️ 注意：`evaluate.py` 对"预测缺页"是**直接抛错**（`Prediction/reference image mismatch`），所以 4 页补齐前连跑都会失败。

| text_cer（每页 CER 的算术平均） | **4.0866**（408.66%） |
| formula_exact_match_rate | 0.0 |
| formula_cer | 1.0 |
| structure_heading_seq_match_rate | 0.0 |

逐页：

| 页 | 参考长度 | 预测长度 | text_CER | 备注 |
|---|---|---|---|---|
| 000020 | 167（28 个 `□`） | 205 | 排除 | 失焦，不得计分 |
| 000028 | 683 | 532 | 0.4390 | 漏掉控制字表 |
| 000037 | 606 | 628 | 0.4958 | 8253 表格基本成型 |
| 000044 | 639 | 717 | 0.9210 | 进入 `D D D` 循环 |
| 000051 | 447 | 7156 | **14.4906** | 退化循环跑满上限 |

### 3.2 `□` 排除的机制与影响

- 规则（`scripts/evaluate.py` L145）：**参考文本中出现任意一个 `□`，整页所有指标置空**（`text_cer`/`formula`/`structure` 全为 `None`，`excluded_reason='unknown_reference'`）。不是"跳过含 `□` 的字符"，是**整页丢弃**。
- 后果：`n_pages=5` 但 **`n_scored_pages=4`**。所有均值分母是 4，不是 5；报告里若写"测试集 5 页 CER"，口径就错了。
- 这套做法的合理性：失焦页的参考本身不可信，任何"预测得分"都是噪声。代价是**样本从 5 掉到 4，均值方差极大**——单页好坏就能主导结论。
- 另一处偏差：主指标只对含 `□` 的页排除，但**不影响 `□` 页的预测仍在文件里**；如果下游误用 `test_pred_512.jsonl` 全 5 条去算，就会把失焦页的幻觉（"个人学习笔记/课程大纲"）当成正常样本。

### 3.3 生成截断的影响（关键）

- **000051 是全部问题的来源**：该页 447 字符参考对上 7156 字符预测，CER = 14.49，占 4.0866 均值的 **3.62/4.09 ≈ 88.6%**。
- 算术复核（未重跑评测）：去掉 000051 后，(0.4390+0.4958+0.9210)/3 = **0.6186**。即"408.66%"这个数字里，**约 347 个百分点来自一页的死循环**。
- 截断本身不制造错误，但**掩盖错误性质**：512 下 000051 在 `OCW3` 之后就被切断，读者看不出"模型其实在循环"；4096 下能看出循环，但数字被放大到无意义。两种口径都不能单独使用，必须配合 `generation_failure` 标记。
- 另有一处系统性偏差要注意：基座输出被 ` ```markdown ` 围栏包裹，而 `postprocess()` **不剥离围栏**，`plain_text()` 也不会去掉反引号 → 每页预测额外多约 15 个字符进入 CER 分母/分子（对 447 字符的页约 3%）。微调版同样带围栏，两侧一致，但绝对值偏高。

### 3.4 公式与结构指标为什么现在没有区分度

- 公式：`n_hyp = 0`（4 页全部）。模型**一个 `$`/`$$` 都没输出**，`extract_formulas` 只能拿到空列表 → `exact_match_rate` 恒为 0、`formula_cer` 恒为 1.0。这不是"公式识别错的 0 分"，而是**"没有产出可比较对象的 0 分"**。
- 结构：参考用 `##`，预测用 `#`/`###` 混排（如 000044 判成 25 个标题 vs 参考 5 个），`heading_seq_match` 必然 0。`table_count_match` 4/4 全 true 是**假阳性**——测试集参考里本来就没有表格（唯一带表格的 235916 在训练集）。

### 3.5 有效页数与"能否比较"

| 项 | 基座 | 微调版 | 能否对比 |
|---|---|---|---|
| 已落盘预测页数 | 5 | 1 | — |
| 有效（可评分）页数 | 4 | **0** | ❌ |
| 环境一致性 | 4-bit + 原图 | 4-bit + LoRA + 原图 | ✅ |
| 上限一致性 | 512 | 512（同一脚本） | ✅ |

**结论：微调前后对比目前不成立。** 微调版缺少 4 个可评分页的预测，`evaluate.py` 也会直接报错。任何"微调把 CER 从 X 降到 Y"的说法此刻都没有数据支撑。

## 5. 最终训练对比报告

### 5.1 可以写入结论的部分（有产物支撑）

5. **结构能力**：标题层级序列 0/4 匹配，`#`/`##`/`###` 混用严重；表格能力在测试集上未被考察（参考无表格）。
