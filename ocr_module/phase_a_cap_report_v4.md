## 3. 判读

1. **上限只对 2/5 页有影响，其余 3 页在两档下逐字节相同**（235932、235946、000012 都在 eos 自然结束）。这个因子的作用面非常窄。
2. **没有任何一页出现"内容被恢复"。**唯一的"自然结束"案例（235955 微调臂）追加的 323 字是同一套臆造模板的续写（`## 6. 处理`、更多 `$A_L/A_H$` 公式），正文 CER 略降（2.981→2.569）但含公式体 CER 反而略升（0.830→0.844），输出仍达参考长度的 2.3 倍。重复检测器没报警，正是已知局限"抓不到格式工整但内容全错"的实例。
3. **000005 微调臂是"重复被延长"的教科书案例**：2048 下依然触顶，追加 1491 字的纯模式复制（交替条目 + 自造编号标题），CER 从 0.888 升到 0.943，耗时翻倍。
4. **基座臂没有任何收益**：235955 在 1024 就已被判重复，加到 2048 只是生成到 1812 token 才停，重复标记依旧，CER 0.997→0.998。
5. **重复不是上限造成的**：000012 微调臂在 639 token、eos 正常结束的情况下两档同样被判重复。这条直接否掉"加大上限能治重复"。

---

## 4. 结论与建议

- **不要把 2048 设为新默认**：5 页里 3 页不受影响、1 页只把臆造模板写得更长、1 页把重复写得更长且耗时翻倍。
- 上限只影响"本来能写更久"的页；本次唯一自然结束的页也并未产出正确内容，说明**瓶颈不在截断**，而在"密集手写页会退化成模板/重复"。
- **重复与臆造应作为独立因子处理**（提示词约束、重复惩罚、或对 000005 这类页做专门诊断），且判定必须看文本而不是只看长度或重复标记。
- 若将来仍要试 2048，应写成独立协议（v4）并逐页记录是否触顶、是否新增了正确内容；不得用"变长"当"变好"。

**本报告不改变既有结论**：`eval_report_v3.md` 的"混合变化"判断不变；本次没跑 test，不构成任何新的效果声明。
